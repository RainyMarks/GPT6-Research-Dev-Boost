# 文献调研

## 检索

本 skill 目录下的 `scripts/search_papers.py` 给出结构化的元数据和引用关系（OpenAlex 加 arXiv），配合网页检索 Google Scholar、DBLP、OpenReview 和会议官网。运行方式：`python -X utf8 <本目录>/scripts/search_papers.py <子命令> ...`。

找最接近的工作、必须比较的基线，或核对想法是否有人做过时，三条路都走：

1. 关键词：`search "<关键词>" --since 2024 --sort cited|recent`，按标题和摘要检索。关键词连同同义词、上位词、相邻领域的叫法都试一遍。
2. 引用追溯：从两三篇核心论文出发，`refs <DOI 或 arXiv ID>` 往前找参考文献，`cites <DOI 或 arXiv ID> --since 2024` 往后找被引。
3. 最新预印本：`arxiv "<关键词>"` 按提交时间倒序列出，看最近一两个月的。OpenAlex 收录 arXiv 有几天到几周的延迟，网页搜索也常漏掉刚发的论文，最接近的工作往往就在这里。

其他：

- `show <ID>` 看单篇的摘要和发表处。脚本输出的 DOI 和 arXiv ID 可以直接交给 `paper-writing` 的 `fetch_bibtex.py`。
- 同时覆盖最近两三年的工作和奠基性工作。写“最新”“目前最好”时注明检索日期。
- 没配 `OPENALEX_API_KEY` 时，同一出口 IP 共享一份每日免费额度，用完返回 HTTP 429；这时改用网页检索，并在汇报里说明。网站打不开时跳过并说明，不为此修改任何网络配置。

## 核对

- 每篇都打开看过再写：至少读摘要、方法和主要结果，核对标题、作者、年份和发表处。
- 区分预印本和已发表论文；预印本已经正式发表的，用正式版本。
- 引用数和会议级别只作参考，不替代对内容的判断。

## 输出

- 来源清单：标题、作者、年份、发表处，以及 DOI、arXiv ID 或链接，逐条写明在哪个页面核对的。“核对过”指这次实际打开或检索到了该文献的页面；凭记忆写的标“未核实”。每条结论都能对应到来源。
- 相关工作按方法类别或问题设定组织，说清每一类的思路、代表工作和局限，不逐篇罗列摘要。
- 写出必须比较的基线和理由，以及研究空白和可以做的方向。

## 新颖性核查

把用户的想法和最接近的已有工作逐项对比（问题设定、核心假设、方法机制、数据、结论），给出“已有人做过”“部分重叠”或“没有找到”的判断，写明检索范围、关键词和检索日期。部分重叠时，写清去掉重叠后还剩什么，差别在假设、机制、设定还是结论上；没检索到的写“未检索到”，不按已有人做过处理。同时写出差异化的切入点：怎样改问题设定、方法或评测，才能和这些工作拉开距离。
