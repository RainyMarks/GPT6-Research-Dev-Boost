# 机器学习实验

## 开跑前

- 数据按独立单元划分：受试者、病人、人物身份、视频、生成器或采集站点，同一单元的样本只出现在一侧。按帧、切片或图块随机划分，会把同一单元拆到训练和测试两边。
- 预处理、归一化、特征选择和数据增强的统计量只在训练集上拟合。
- 选模型、调参、早停和定阈值都用验证集；测试集只在最终评估时用一次。
- 基线和本方法使用同一数据、同一预处理、同一评测脚本和相近的调参预算。照抄论文里的数字时，注明出处和设置差异。

## 长时间训练

- 启动前先用极小规模跑通一遍（几个 step 或一小部分数据），确认能跑、loss 在下降、日志和 checkpoint 正常写出。这是与风险相称的检查，不属于仪式性验证。新方法先用最小的实验判断它值不值得继续，再放大规模。
- 正式训练放到后台：日志写文件，定期保存 checkpoint，支持断点续训。启动后汇报命令、日志位置和预计时长，不在回合里干等。
- 只按 PID 结束自己启动的进程。GPU 或内存不够时，报告占用情况，由用户决定。
- 新结果写到新目录，不覆盖、不删除已有的数据集、checkpoint 和实验结果。

## 核查结果

- 报告多个随机种子的均值和标准差，不挑最好的一次。差距小时做显著性检验，或说明差异不显著。
- 结果好得反常（例如检测准确率接近 100%、远超已发表方法）时，先查数据泄漏、评测脚本错误和捷径特征，查清再下结论。捷径特征包括压缩格式、分辨率、文件名、水印、数据来源和采集设备的差异。
- 发现泄漏或评测问题时，用修正后的协议做一次只读的重新评测：按单元重新划分、在验证集上定阈值、跑几个随机种子。结果写进汇报或新文件，不覆盖原有结果，不改训练脚本的默认行为；汇报里同时给出修正前后的数字。需要长时间重新训练的，说明问题和影响，由用户决定。
- 负面结果和不及预期的结果如实报告，并给出下一步排查方向。

## 复现

记录 git commit、配置、随机种子、环境版本和数据版本。沿用项目已有的实验记录方式（wandb、TensorBoard、CSV、日志目录），没有的话把记录写进汇报。
