# 实验

主干按机器学习实验写；论断—证据表、按独立单元划分、同协议对比、多次重复、逐层排查这些原则对所有实验都适用。系统性能实验、用户研究等其他类型，再读文末“按实验类型和领域补充”里对应的文件。

## 选实验协议

设计实验时先写论断—证据表：每条论断对应一个能让人信服的实验，每个实验只承担一个论证任务；对应不上论断的实验不做。一篇方法论文通常需要四类实验：

- 前置实证分析：提方法之前，证明问题存在并找到成因，作为动机。
- 对比实验：在目标领域通行的数据集和指标上，与最强的基线比较。
- 消融实验：逐个去掉或替换核心组件，证明它有用。
- 机制分析：解释为什么有用，验证方法确实通过声称的机制起作用。

基线、数据集和指标怎么选，如何排除“增益只来自更多参数或更多调参”这类替代解释，以及每类实验的具体做法，见 `references/protocol.md`。

## 开跑前

- 数据按独立单元划分：共享来源、会让测试样本在训练集里有“近亲”的样本算一个单元，例如同一用户或受试者、同一会话、同一文档、同一代码仓库及其 fork、同一源素材、同一主机或采集站点。同一单元的样本只出现在一侧。按帧、句子、函数、图块或流随机划分，会把同一单元拆到两边。论断涉及未来数据时按时间划分。
- 预处理、归一化、特征选择和数据增强的统计量只在训练集上拟合。
- 选模型、调参、早停和定阈值都用验证集；测试集只在最终评估时用一次。
- 基线和本方法使用同一数据、同一预处理、同一评测脚本和相近的调参预算。照抄论文里的数字时，注明出处和设置差异。

## 长时间运行

- 启动前先用极小规模跑通一遍（几个 step 或一小部分数据），确认能跑、loss 在下降、日志和 checkpoint 正常写出。这是与风险相称的检查，不属于仪式性验证。新方法先用最小的实验判断它值不值得继续，再放大规模。
- 正式训练、批量推理和大规模测量放到后台：日志写文件，定期保存 checkpoint 或中间结果，支持断点续跑。启动后汇报命令、日志位置和预计时长，不在回合里干等。
- 只按 PID 结束自己启动的进程。GPU 或内存不够时，报告占用情况，由用户决定。
- 新结果写到新目录，不覆盖、不删除已有的数据集、checkpoint 和实验结果。

## 核查结果

- 报告多次运行（多个随机种子、多次重复测量）的均值和标准差或置信区间，不挑最好的一次。差距小时做显著性检验，或说明差异不显著。
- 结果好得反常（例如准确率接近 100%、远超已发表方法、提速远超硬件上限）时，先查数据泄漏、测试集污染、评测脚本错误和捷径特征，查清再下结论。捷径特征指和标签相关、和任务无关的属性，例如数据来源和采集批次、文件格式和长度、文件名或 ID、时间戳、采集设备，可以用 `data-gathering` 的 `scripts/check_dataset.py` 检查。
- 发现泄漏或评测问题时，用修正后的协议做一次只读的重新评测：按单元重新划分、在验证集上定阈值、跑几个随机种子。结果写进汇报或新文件，不覆盖原有结果，不改训练脚本的默认行为；汇报里同时给出修正前后的数字。需要长时间重新训练的，说明问题和影响，由用户决定。
- 负面结果和不及预期的结果如实报告。结果推翻或削弱原论断时，按 `paper-writing` 的要求写 **换个角度**：至少两个比原论断更有用的替代主张，低成本的那个跑一个新实验验证（刚做完的实验不算）。

## 结果不如预期时

按顺序排查，前一层的问题修好、重跑之后再看下一层：

1. 实现：bug、数据管道、预处理、评测脚本。
2. 配置：超参数、训练预算、是否收敛、和基线的调参预算是否相当。
3. 评测协议：数据划分、指标、阈值、与基线是否同一协议。
4. 机制本身：在可控条件下（小数据、合成数据、去掉干扰因素）它是否起作用。
5. 问题设定：问题本身是否需要重新定义。

几分钟能跑完的修复直接跑；需要长时间训练的，写出计划交给用户。执行失败、比较无效、结果不利是三种情况，分开报告。确认问题在第 4、5 层之后，才改方法或收窄主张，并写明是哪个结果否定了哪一层。

## 复现

记录 git commit、配置、随机种子、环境版本和数据版本。沿用项目已有的实验记录方式（wandb、TensorBoard、CSV、日志目录），没有的话把记录写进汇报。

## 按实验类型和领域补充

- 实验类型：系统、网络、数据库、编译器、ML 系统等以性能、开销或可扩展性为论断的实验读 `references/systems.md`；用户研究、可用性测试、人工评测模型输出读 `references/human-study.md`。
- 领域：基于学习的安全系统（恶意软件、漏洞、入侵检测、流量分类、欺诈检测）读 `references/security.md`；检测和取证（AIGC 生成内容、深度伪造、可信取证）读 `references/detection.md`；医学影像读 `references/medical.md`；数字水印读 `references/watermark.md`。
- 没有对应文件的领域，按主干做，把该领域公认的基准、指标和常见陷阱检索出来写进汇报。数据集本身的采集、划分和体检用 `data-gathering` skill。
