# 数据采集与数据集构建

泄漏、重复、测试集污染和捷径特征会让任何方法看起来都有效，标签错误和采样偏差会让结论推不到真实场景。采集时把来源、派生关系和处理过程记进清单，使用前用脚本体检，问题在数据阶段解决。

## 动手前先回答

1. **论断要推广到哪里**：同分布的新样本、没见过的用户或来源、以后的时间、别的数据集或环境。这决定划分方式（对照表见 `experiments` 的“选协议”），也决定要采集多少种来源和条件。
2. **什么算一个独立单元**：凡是共享来源、会让测试样本在训练集里有“近亲”的样本，归为一个单元。例如同一用户、作者或受试者，同一会话，同一文档或网页，同一代码仓库及其 fork，同一提示词模板，同一源素材（源图、源视频、源录音），同一主机或采集批次。同一单元的样本只落在一侧。
3. **标签从哪来、有多准**：人工标注、规则、日志、实验时间表、模型生成，各自的错误率怎么估计。

## 划分

- 按论断选一种主划分。几种约束同时满足会丢掉大量数据时（例如每个仓库都跨越整个时间段，又要按时间、又要仓库不重叠），先算出各方案保留多少样本、每个划分每类有多少，再选；放弃的约束写成补充实验。
- 交付的划分要能用：每个划分每类至少几十个样本，验证集足够用来选模型和定阈值。达不到时换方案或补数据，给出一个能用的划分和它的代价，不交付用不了的划分。
- 先去重再划分：完全相同和近似重复的样本归成一组，组内留一个，或整组放在同一侧。

## 清单

- 每个样本一行写进清单 CSV：ID、路径或内容、标签、划分、独立单元、来源（网址、数据集名和版本、API 和查询条件、仓库和 commit）、获取时间、许可、处理过程、生成参数（合成数据的模型和版本、提示词、采样参数或种子）。之后的划分、体检和数据说明都从清单出发。
- 原始数据只读保存，处理结果输出到新目录；采集脚本、配置和清单进版本控制。

## 按来源

- **公开数据集和基准**：从官方渠道获取，记版本和官方划分，官方提供哈希时比对一次；需要签协议或申请的，告诉用户去申请。用之前检索它的勘误、复查论文和 issue，有修正版用修正版。官方划分有已知泄漏时按单元重新划分，同时报告官方划分下的结果，便于和已有工作比较。
- **网页和 API**：遵守服务条款、robots.txt 和速率限制。保存原始响应和抓取时间（网页和接口返回会变），记录查询条件；抓取范围本身就是采样方式，写进数据说明。
- **代码和软件仓库**：fork、复制粘贴和自动生成的文件造成大量重复，重复会把模型指标抬高最多 100%（Allamanis, Onward! 2019, doi:10.1145/3359591.3359735）。按仓库及其 fork 分组，再做文件和函数级去重；记录许可证；按时间划分时用 commit 时间。
- **文本和大模型评测数据**：标准数据集里超过 4% 的验证集和训练集重叠（Lee et al., ACL 2022, doi:10.18653/v1/2022.acl-long.577），先去重再划分，规范化后的完全重复和改写都要查。评测预训练或微调过的模型时查测试集污染：测试题是否出现在公开语料或训练数据里（n-gram 重叠、检索原文），或只用模型训练截止之后发布的题目。
- **合成数据**（生成模型、大模型、模拟器、程序生成）：记录生成器和版本、提示词、采样参数；过滤后抽一部分人工核对；生成数据的模型和被评测的模型不用同一个或同一家族；保留一份真实数据的测试集，报告从合成到真实的差距。
- **测量、日志和测试床**：记录环境（硬件、系统和软件版本、拓扑、负载、时间同步）。操作用脚本按时间表执行，时间表就是标签来源。保存原始记录（trace、日志、pcap），特征从原始记录重新提取，提取工具的版本和参数写进清单。
- **人工标注和用户研究**：涉及人类参与者先过伦理审批并取得知情同意。标注先写指南、做试标，计算标注者间一致性，分歧按规则裁决；用大模型标注时，在人工标注的子集上报告它和人的一致性。读 `references/annotation.md`。

## 构造时控制差异

- 不同类别、不同条件的样本走同一条采集和处理链：同样的来源和时间段、同样的格式和长度分布、同样的预处理。差异只留在研究的那个因素上；对不齐的差异写成清单里的属性列，交给体检脚本衡量。
- 类别比例按部署场景定：真实场景里正样本很少（攻击、恶意软件、欺诈）时，测试集按真实比例构造，或另备一份按真实比例抽样的测试集。
- 批量采集和生成放到后台：日志写文件，支持断点续跑，每批记录参数。先用极小规模跑通，人工看过输出再放大。

## 体检

训练和评测前、每次增删数据后运行，按数据情况选参数：

```
python -X utf8 <本目录>/scripts/check_dataset.py manifest.csv --split split --label label \
    --group user --group repo --path path --text content --near content --time created_at \
    --attr source --attr length
```

- 脚本检查：空标签或空划分；`--group` 列的同一个值跨越多个划分；文件内容相同（`--path`）或忽略大小写和空白后文本相同（`--text`）的样本跨划分或标签不同；跨划分的改写和近似重复（`--near`）；评测样本不晚于训练样本（`--time`）；单个属性（`--attr`）在训练集上拟合的规则，到评测集上能把标签预测到什么程度。没有分类标签的数据（生成、检索、系统 trace）省略 `--label` 和 `--attr`。
- `--near <列>` 按稀有词加权比较文本和代码，同一模板、不同实体的样本不会被当成重复。看它打印的各阈值命中数，阈值选在命中数的断层处，并抽查例子。图片和音视频的近似重复用感知哈希另查，把簇 ID 写成一列，作为 `--group` 交给脚本。
- FAIL（泄漏、重复、坏行）修好再用。捷径 WARN 有两种处理：对齐数据，或保留并在实验里控制它（按该属性分层报告结果、做消除该差异后的对照）。
- 按类别和来源随机抽样人工检查，每层至少几十条：标签是否正确、样本是否有效、有没有坏文件。错误比例写进汇报。
- 体检报告和抽查结果随数据集一起保存，写进汇报。

## 授权、隐私和发布

- 个人数据包括人脸和声音、用户生成内容、日志里的账号和 IP、网络流量的载荷。采集前确认许可、服务条款或使用协议覆盖研究用途，记在清单的来源列里。
- 发布数据集或特征前去标识：删除或替换直接标识符，IP 做前缀保持的匿名化，载荷去掉或只发特征；核对去标识后仍能否通过组合字段认出个人。
- 投稿需要数据说明时，按 Datasheets for Datasets（Gebru et al., arXiv:1803.09010）的七类问题写：动机、组成、采集过程、预处理和标注、用途、分发、维护。清单字段能直接回答其中大部分。
