# 基于学习的安全系统

适用于恶意软件检测、漏洞发现、二进制分析、入侵检测、流量分类、欺诈和垃圾信息检测等。按 Arp 等人总结的十个陷阱逐项核对（*Dos and Don'ts of Machine Learning in Computer Security*, USENIX Security 2022, arXiv:2010.09470；他们复查的 30 篇顶会论文里，数据窥探出现在 57%，只在实验室评测出现在 47%）：

| 陷阱 | 做法 |
| --- | --- |
| 采样偏差 | 写明数据代表什么环境、什么时期、什么样本来源；测试集的类别比例接近真实部署。论断超出这个范围时，补跨数据集或跨环境的测试。 |
| 标签不准 | 标签来源写清（沙箱、杀软多引擎投票及阈值、攻击时间表、威胁情报、人工）；抽查错标比例；有勘误的数据集用修正版。 |
| 数据窥探 | 按时间划分，训练样本全部早于测试样本；归一化、特征选择、过采样只在训练集上做。随机划分只作为参考结果。 |
| 伪相关 | 用 `data-gathering` 的 `check_dataset.py` 测与任务无关的字段（来源、编译器或打包工具、文件大小、时间戳、IP、端口）能否单独预测标签；去掉这些差异再跑一次，报告前后差距。 |
| 参数选择偏差 | 超参数和阈值在验证集上定，测试集只用一次。 |
| 基线不当 | 除了最新的深度模型，加上在同一特征上调好的传统模型（随机森林、梯度提升树），以及规则、签名或现有工具。简单基线打平时，如实报告。 |
| 指标不当 | 按类别报告召回率和 macro-F1；给出低误报工作点（FPR 为 10⁻³、10⁻⁴）下的检出率和 PR 曲线。 |
| 基率谬误 | 测试集的恶意或攻击比例远高于真实部署（例如对半）时，精确率和 F1 被抬高。按部署场景的比例（有来源时引用，没有时取 1%、10% 几档）重新抽样测试集或换算精确率，报告每天多少误报、告警里多少比例是真的。 |
| 只在实验室评测 | 讨论部署约束：吞吐、时延、资源占用、需要多久重训；能拿到真实环境数据的，做一次真实环境测试。 |
| 威胁模型不当 | 写清攻击者知道什么、能改什么；对抗评测在问题空间里做，改过的样本要能运行、符合协议、保留恶意功能。只在特征空间里改、对应不到真实样本的扰动，只作参考。 |

另外：

- 概念漂移：按时间切出多个后续测试窗口，报告性能随时间的变化。恶意软件检测同时满足时间一致（训练早于测试，良性和恶意样本取自同一时期）和空间一致（测试集恶意比例接近真实），否则结果会被抬高（Pendlebury et al., TESSERACT, arXiv:1807.07838）。
- 开放世界：训练时没见过的攻击类型、恶意家族或应用，单独作为测试集，报告检出或拒识的能力（Sommer and Paxson, IEEE S&P 2010, doi:10.1109/SP.2010.25）。
- 网络流量：报告处理速率（包每秒、Gbps）和早期检测需要的包数；声称不依赖明文的加密流量分类，报告去掉 SNI、证书等明文字段后的结果。数据采集见 `data-gathering` 的 `references/traffic.md`。
