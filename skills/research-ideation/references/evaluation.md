# 创新评估

逐项回答下表的问题，每项写依据（检索到的文献、前置实验结果或推理），给出强、一般、弱的判断，以及让它变强的最小改动。缺检索或缺实验只降低把握，不降低评价，写成“未检索”“待验证”。

| 维度 | 要回答的问题 |
| --- | --- |
| 问题的真实性和重要性 | 有没有前置证据表明问题存在？解决了它，谁受益，受益多少？ |
| 洞见 | 是否推翻或修正了一个默认假设，或揭示了一个被忽略的现象？这个洞见能否开出一个方向，让别人用其他技术接着做？ |
| 新的对象或机制 | 是否定义了新的数学对象、学习目标或学习机制？换个名字或换个模块之后，机制是不是其实没变？已知组件也可以支撑新的相互作用，关键看改变了哪个假设、哪个操作、带来什么后果。 |
| 与最接近工作的差别 | 去掉已有工作做过的部分，还剩什么新东西？差别在假设、操作还是结论上？ |
| 机制的合理性 | 假设之间是否自洽？有没有清楚的理由说明这个干预会改变可观察的结果？逻辑矛盾才扣分，尚未验证不扣分。 |
| 可证伪和可验证 | 什么结果会证伪它？能否设计出消融实验证明“有用”、机制分析解释“为什么有用”？ |
| 辨识度 | 放进同期投稿里，能否用一句话让人记住？标题和核心图能不能一眼传达出来？ |
| 简洁 | 每个组件是否都服务于核心想法？ |
| 目标领域的偏好 | 目标期刊或会议更看重什么：理论深度、效果、新问题还是应用价值？看它近两年同方向的录用论文来判断。不同领域、不同期刊的偏好各不相同。 |

一个方向判为“弱”时，先给出补救路线：换问题设定、换机制，或补哪项证据。只有找不到任何有意义的表述时才建议放弃，并写明原因。
